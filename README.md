## Что находится в проекте

- `bootloader\boot.asm` — исходный код BIOS/MBR-загрузчика.
- `kernel\kernel.asm` — точка входа и оболочка загрузочного ядра.
- `kernel\commands\` — встроенные команды ядра, каждая в отдельном ASM-файле.
- `kernel\drivers\` — драйверы консоли и FAT16.
- `apps\hello.asm` — исходник демонстрационной real-mode программы `.COM`.
- `dos\` — отдельная DOS-подобная оболочка для Windows на Python.
- `tools\` — сборка образа, установщик приложений и QEMU-интеграционный тест.
- `tests\` — модульные тесты Python.
- `dist\dos.img` — собранный raw-образ диска на 2 ГиБ; создаётся сборкой.
- `virtual-disks\C\` — изолированный виртуальный диск оболочки Python.

## Возможности загрузочного ядра

Система загружается в Legacy BIOS/CSM, показывает текстовую консоль и работает
с одним диском-образом FAT16. В корне FAT16 доступны команды:

| Команда | Назначение |
|---|---|
| `HELP` | Список команд |
| `CLS` | Очистка экрана |
| `VER` | Информация о версии |
| `ECHO текст` | Вывод текста |
| `DIR` | Список файлов корневого каталога |
| `TYPE FILE.TXT` | Вывод содержимого файла |
| `WRITE FILE.TXT текст` | Создание или перезапись файла |
| `APPEND FILE.TXT текст` | Добавление текста в файл |
| `EDIT FILE.TXT новый_текст` | Замена содержимого файла |
| `DEL FILE.TXT` | Удаление файла |
| `RUN PROGRAM.COM` | Запуск real-mode программы `.COM` |
| `REBOOT` | Перезагрузка |
| `HALT` | Остановка системы |

Имена в загрузочной системе должны соответствовать DOS 8.3. Поддерживаются
только корневой каталог и файлы размером примерно до 60 КиБ. Каждая команда
оболочки ядра принимает короткую строку; большой текст можно дописывать
несколькими вызовами `APPEND`.

Кроме загрузочного ядра, проект содержит отдельную оболочку на Python.
Она использует папку `virtual-disks\C` и реализует другой набор команд:
`HELP`, `DIR`, `CD`, `COPY`, `DEL`, `REN`, `MD`, `RD`, `TYPE`, `TREE`,
`FIND`, `FC`, `ATTRIB`, `SET`, `PATH`, `PROMPT`, `DATE`, `TIME`, `VOL`,
`ECHO`, `CLS`, `VER`, `MORE`, `PAUSE`, `IF`, `FOR`, `CALL`, `GOTO`, `REM`
и `EXIT`. Это самостоятельный режим, он не является частью загрузочного
образа.

## Сборка и запуск в Windows

Понадобятся Python 3 и NASM для сборки. Для запуска и интеграционного теста
также понадобится QEMU. Откройте PowerShell в каталоге проекта.

Соберите образ:

```powershell
.\build.ps1
```

Скрипт создаёт `dist\dos.img` — raw-образ размером 2 ГиБ. Перед сборкой
проверьте, что на диске достаточно свободного места.

Запустите графическую консоль в QEMU:

```powershell
.\run-qemu.ps1
```

Или вызовите QEMU напрямую:

```powershell
qemu-system-x86_64.exe -machine pc -m 16 -drive file=dist\dos.img,format=raw,if=ide -boot c
```

После загрузки попробуйте:

```text
HELP
DIR
TYPE MULTI.TXT
RUN HELLO.COM
```

## Установка сторонних приложений

Ядро может запускать только real-mode `.COM`, который укладывается в лимит
размера и использует реализованные функции DOS API. Windows `.exe`, DOS
`.EXE` и многие старые программы несовместимы.

Установите `.COM` в стандартный образ:

```powershell
.\install-app.ps1 "C:\Downloads\APP.COM"
```

Если длинное имя источника не подходит под DOS 8.3, задайте короткое имя:

```powershell
.\install-app.ps1 "C:\Downloads\long-application.com" -Name "APP.COM"
```

Для установки приложения из ZIP используйте:

```powershell
.\install-app.ps1 "C:\Downloads\PACKAGE.ZIP" -Archive
```

ZIP-установщик копирует подходящие файлы только из корня архива. Подкаталоги
и имена, не подходящие формату 8.3, пропускаются. Установка набора файлов не
гарантирует, что программа запустится: ей также нужен поддерживаемый DOS API.

Для пользовательского образа укажите `-Image`:

```powershell
.\install-app.ps1 "C:\Downloads\APP.COM" -Image "C:\Images\test.img"
```

Для замены существующего файла добавьте `-Replace`. Перед установкой или
удалением закройте QEMU, если он использует этот образ. Приложения, установленные
в стандартный образ, сохраняются в `apps\installed` или
`apps\installed_packages` и включаются при следующих сборках. Данные,
созданные внутри гостевой ОС, автоматически не сохраняются при пересборке.

Запускайте только приложения из источников, которым доверяете: `.COM`
исполняется в real mode и может обращаться к памяти и оборудованию.

## Тестирование

Запустите модульные тесты Python:

```powershell
python -m unittest discover -s tests -v
```

Интеграционный тест ядра в QEMU:

```powershell
.\test-qemu.ps1
```

Интеграционный тест проверяет загрузку, геометрию FAT16, файловые операции,
запуск `.COM` и сохранность данных после перезагрузки. Запускайте его, когда
QEMU не работает с тем же образом.

Для запуска отдельной Python-оболочки:

```powershell
python -m dos
```

## Эксперименты и устройство проекта

Хорошие первые задачи для изучения:

1. Посмотреть, как загрузчик передаёт управление ядру, начиная с
   `bootloader\boot.asm` и `kernel\kernel.asm`.
2. Разобрать одну команду в `kernel\commands\` и проследить, как она вызывает
   функции драйвера FAT16.
3. Изменить исходник `apps\hello.asm`, собрать систему и проверить программу
   в QEMU.
4. Посмотреть на структуры FAT16 и проверки установщика в `dos\fat16_image.py`
   и `dos\app_archive.py`.
5. Добавить тест к изменённой функции и запустить соответствующую проверку.

Сборка использует NASM и создаёт загрузочный образ. Устройство файловой
системы, работа с диском, обработчики прерываний и ограничения real mode —
полезные темы для дальнейших экспериментов. Изменения лучше сначала проверять
в QEMU, а не на единственном физическом компьютере.

## Запуск на физическом компьютере

Образ предназначен только для Legacy BIOS/CSM; компьютеры с одним лишь UEFI
не загрузят его. Сначала убедитесь, что образ работает в QEMU. Запись raw-образа
на USB-накопитель уничтожит данные на выбранном накопителе. Перед записью
сделайте резервную копию и особенно внимательно проверьте выбранное устройство:
не выбирайте внутренний системный диск. Для загрузки затем включите Legacy/CSM
в настройках прошивки ПК и выберите USB-накопитель.

Это прототип для обучения и тестов. Не храните в нём единственные копии важных
данных и не используйте вместо современной защищённой ОС.

## Публикация проекта на GitHub

Для публикации исходного кода обычно достаточно создать пустой репозиторий
GitHub и загрузить исходники и скрипты. Не добавляйте в Git виртуальное
окружение `.venv`, временные файлы `__pycache__` и тяжёлые сборочные артефакты.
`dist\dos.img` занимает 2 ГиБ, поэтому его не следует загружать как обычный файл
в GitHub-репозиторий; укажите в описании проекта, что образ можно собрать
локально командой `.\build.ps1`.

Перед публикацией проверьте, что в исходниках нет паролей, токенов и личных
данных. Прочитайте лицензию каждого стороннего приложения, которое вы
распространяете вместе с проектом; безопаснее публиковать только собственные
исходники и ссылки на внешние загрузки.
